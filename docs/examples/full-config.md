# Full Config Example

You do not need all of these settings for the first run. Start with the minimal config from [Getting started](../getting-started.md), then copy only the parts your project needs.

This example shows a larger configuration with comments, defaults, focused diagrams, raw output, Mermaid output, and DOT-specific styling.

```yaml
provider: postgres
connectionString: "${DB_CONNECTION}"

database:
  commandTimeoutSeconds: 30

comments:
  enabled: true
  overrides:
    tables:
      - schema: public
        name: Users
        comment: Application users
        columns:
          Id: Internal user identifier
          Email: Login email

defaults:
  output:
    format: markdown
    markdown:
      fenceLanguage: mermaid
      header: |
        # Database schema

        Generated by DbSketch.

  diagram:
    renderer: mermaid
    direction: LR
    style: readable
    compact: true
    tableHeaderLayout: "{fullName} | {comment}"
    columnLayout: "{name} | {type} | {comment} | {keys}"

    show:
      schemaName: true
      columnTypes: true
      nullability: true
      primaryKeys: true
      foreignKeys: true
      foreignKeyLabels: true
      selfReferencingForeignKeys: true
      tableComments: true
      columnComments: true

    comments:
      maxLength: 80

    mermaid:
      emitDirection: false

    dot:
      graph:
        fontName: Helvetica
        fontSize: 16
        nodesep: 0.55
        ranksep: 0.9
        backgroundColor: "#FFFFFF"
      node:
        fontName: Helvetica
        fontSize: 10
      edge:
        fontName: Helvetica
        fontSize: 9
        color: "#555555"
        penWidth: 1.1
        arrowSize: 0.7
      table:
        borderColor: "#777777"
        headerBackground: "#F1F3F5"
        cellPadding: 4

diagrams:
  - name: full
    title: Full database schema
    include:
      tables:
        - "public.*"
    exclude:
      tables:
        - "public.audit_*"
        - "public.__EFMigrationsHistory"
    output:
      path: docs/db/full.md

  - name: auth
    title: Auth schema
    include:
      tables:
        - "public.Users"
        - "public.Roles"
        - "public.UserRoles"
        - "public.Permissions"
    output:
      path: docs/db/auth.md

  - name: full-dot
    title: Full database schema
    diagram:
      renderer: dot
      style: readable
      columnLayout: "{name:bold} {type:color=#666666}\n{comment:color=#666666,fontSize=9} | {keys}"
      tableHeaderLayout: "{table:bold}\n{comment:color=#666666,fontSize=9}"
    output:
      path: docs/db/full.dot
      format: raw

  - name: auth-mermaid
    title: Auth schema
    include:
      tables:
        - "public.Users"
        - "public.Roles"
    diagram:
      renderer: mermaid
      mermaid:
        emitDirection: false
    output:
      path: docs/db/auth.mmd
      format: raw
```

## Notes

The root `provider` and `connectionString` settings are still the only required settings.

Use `defaults` when most diagrams should share the same renderer, layout, output format, or comment behavior.

Use per-diagram `diagram` and `output` sections when one diagram needs a different renderer, file path, or raw output format.

Use `include` and `exclude` to keep diagrams focused. Foreign keys are rendered only when both related tables are included in the same diagram.
