# Full Config Example

You do not need all of these settings for the first run. Start with the minimal config from [Getting started](../getting-started.md), then copy only the parts your project needs.

This example shows a larger configuration with comments, defaults, focused diagrams, raw output, Mermaid output, and DOT-specific styling.

```yaml
provider: postgres
connectionString: "${DB_CONNECTION}"

database:
  commandTimeoutSeconds: 30

comments:
  enabled: true
  overrides:
    tables:
      - schema: public
        name: Users
        comment: Application users
        columns:
          Id: Internal user identifier
          Email: Login email

defaults:
  output:
    format: markdown
    markdown:
      fenceLanguage: mermaid
      header: |
        # Database schema

        Generated by DbSketch.

  diagram:
    renderer: mermaid
    direction: LR
    style: readable
    compact: true
    tableHeaderLayout: "{fullName} | {comment}"
    columnLayout: "{name} | {type} | {keys} | {nullable}"

    show:
      schemaName: true
      foreignKeyLabels: true
      selfReferencingForeignKeys: true
      tableComments: true

    comments:
      maxLength: 80

    mermaid:
      emitDirection: false
      tableCommentsOnNewLine: true

    dot:
      graph:
        fontName: Helvetica
        fontSize: 16
        nodesep: 0.55
        ranksep: 0.9
        backgroundColor: "#FFFFFF"
      node:
        fontName: Helvetica
        fontSize: 10
      edge:
        fontName: Helvetica
        fontSize: 9
        color: "#555555"
        penWidth: 1.1
        arrowSize: 0.7
      table:
        borderColor: "#777777"
        headerBackground: "#F1F3F5"
        cellPadding: 4

diagrams:
  - name: full
    title: Full database schema
    include:
      tables:
        - "public.*"
    exclude:
      tables:
        - "public.audit_*"
        - "public.__EFMigrationsHistory"
    output:
      path: docs/db/full.md

  - name: auth
    title: Auth schema
    include:
      tables:
        - "public.Users"
        - "public.Roles"
        - "public.UserRoles"
        - "public.Permissions"
    output:
      path: docs/db/auth.md

  - name: full-dot
    title: Full database schema
    diagram:
      renderer: dot
      style: readable
      columnLayout: "{name:bold} {type:color=#666666}\n{comment:color=#666666,fontSize=9} | {keys}"
      tableHeaderLayout: "{table:bold}\n{comment:color=#666666,fontSize=9}"
    output:
      path: docs/db/full.dot
      format: raw

  - name: auth-mermaid
    title: Auth schema
    include:
      tables:
        - "public.Users"
        - "public.Roles"
    diagram:
      renderer: mermaid
      mermaid:
        emitDirection: false
    output:
      path: docs/db/auth.mmd
      format: raw
```

## Notes

The root `provider` and `connectionString` settings are still the only required settings.

Use `defaults` for settings shared by most diagrams: renderer, layout, output format, style, and comment behavior.

Use `columnLayout` to control which column attributes are rendered and in what order. The `show` section is for relationship visibility and table-level display options, not for ordinary column text.

Use `diagrams` when one huge database diagram would be hard to read. This is useful when tables are grouped by schema, by naming convention, or by business area, and you want several focused diagrams instead of one very large diagram.

A diagram target should describe one knowledge area: which tables belong to it, what title it should have, where the output should be written, and whether it needs a renderer or layout override.

Use per-diagram `diagram` and `output` sections only when a specific diagram needs a different renderer, layout, file path, or raw output format. Otherwise, keep shared settings in `defaults`.

Use `include` and `exclude` to keep diagrams focused. Foreign keys are rendered only when both related tables are included in the same diagram.
